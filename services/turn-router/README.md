# Turn Router

Model-neutral граница Workspace. Основной `CapabilityCandidateRouter` сравнивает
запрос с декларативными descriptions/examples только включённых модулей. Он
возвращает не план, а максимум три допустимых кандидата. Это advisory retrieval:
пустой результат не доказывает, что пользователь просто разговаривает, а наличие
кандидата не разрешает действие.

Retrieval нормализует Unicode, сравнивает токены с учётом переставленных букв и
выбирает лучшее ограниченное окно длинного сообщения. Нормализованная строка не
передаётся в Intent Compiler и никогда не заменяет исходное evidence. Полный
список semantic operations строится только из descriptors включённых модулей и
доступен для introspection. По ADR-021 это больше не автоматическое разрешение
fallback при отсутствии независимых признаков пользовательской просьбы.

Turn classifier отделяет conversation/action/mixed. Workspace дополнительно
проверяет, что выделенный action-фрагмент сохраняет найденную capability; при
противоречии semantic route получает полный неизменённый запрос. Ни один router
не строит план и ничего не исполняет: это делают Intent Compiler, Permission
Gateway и Orchestrator. Решение зафиксировано в `ADR-019`.

Для pure conversation/action доверенным фрагментом всегда является полный
текущий пользовательский текст: исправленная моделью опечатка или случайно
скопированная история отбрасывается. Только mixed split обязан состоять из
точных непересекающихся подстрок. Leading negation RU/EN закрывается общим
safety guard, а malformed classifier допускает один повтор без истории и затем
остаётся без tools.

`requested_operations` — отдельная консервативная граница: request cues берутся
из первых слов module-owned examples, не из description. Примеры должны начинаться
с просьбы/уточнения, не с нейтрального описания темы. Допускается одна опечатка
в длинном cue; quoted примеры и ближайшие отрицания исключаются. Неузнанная
формулировка остаётся без tools. Это не заявление о полном понимании языка.

Production дополняет этот слой `SemanticCapabilitySelector`: он строит embeddings
только для описаний из уже отфильтрованного runtime-каталога и возвращает не
более трёх кандидатов. По умолчанию используется локальный
`qwen3-embedding:0.6b` через credential-free loopback Ollama. Векторы capability
кэшируются на время процесса, запросы хранятся в ограниченном LRU. Ошибка,
отсутствие или медленный ответ модели размыкает semantic-ветку на 60 секунд и
оставляет рабочим лексический маршрут.

`HybridCapabilityRouter` объединяет оба набора кандидатов, но не определяет
`conversation/action`, не создаёт intent и не разрешает выполнение. Решение о
типе сообщения остаётся за Turn Router/Qwen, предложение операции проходит
закрытую schema, а права — Permission Gateway. Полные границы описаны в
`ADR-025`.
