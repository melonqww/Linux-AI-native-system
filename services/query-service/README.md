# Query Service

Единая read-only точка поиска поверх метаданных Storage Catalog и содержимого
SQLite FTS. PDF сначала безопасно извлекается модулем `documents.pdf`, затем
индексируется без повторного чтения исходного файла текстовым индексатором.

Если runtime передал локальный embedding-provider, content/hybrid-поиск также
использует ограниченный семантический слой. Поэтому русская формулировка может
найти английский фрагмент с тем же смыслом. Это необязательное расширение:
недоступность модели оставляет рабочим SQLite FTS и не запускает загрузку модели.
До embedding-provider доходят только фрагменты файлов, которые Storage Catalog
уже отфильтровал по диску, metadata-фильтрам и разрешению `content`; содержимое
томов `metadata` и `none` провайдеру не передаётся.

Расширение, том и имя являются фильтрами. Если задан текст содержимого, сервис
не добавляет нерелевантные документы только потому, что у них совпало
расширение.

Для непустого `text` план также передаёт `content_match`: `semantic` означает
тематический поиск, а `exact_phrase` — запрос на совпадение указанной фразы.
Различие уже является частью capability-контракта; фактическое разделение
поисковых алгоритмов будет добавлено следующим этапом.

`DocumentQuery.mode` задаёт смысл явно: `metadata` ищет по имени, расширению или
диску без content query; `content` использует полнотекстовый индекс; `hybrid`
совмещает содержимое с metadata-фильтрами. Новые планы передают mode явно, а
старые внутренние планы нормализуются детерминированно без таблицы фраз.

Capability публикует только реально исполняемые фильтры. Определение языка
документа пока не реализовано, поэтому `languages` не входит в публичный
контракт: переданный устаревшим клиентом фильтр отклоняется, а не игнорируется.

`QueryRuntimeApplication` валидирует JSON панели и преобразует его в
`DocumentQuery`. Из результатов можно сохранить immutable snapshot-коллекцию,
которая затем передаётся в Materialize Service.

File Search R1 добавляет стабильный page envelope с `total_matches`, признаком
точности total и coverage выбранных томов. Совместимый `/v1/search` возвращает
список, а `/v1/search-page` — результаты вместе с пагинацией и покрытием.
Metadata-результат не исчезает из-за ошибки чтения: `content_state` различает
`indexed`, `pending`, `unavailable`, `not_permitted` и `unsupported`, а
`content_reason` содержит только ограниченный публичный код.

Каталогизация диска и извлечение PDF не выполняются внутри интерактивного
поискового запроса: это сохраняет низкую задержку интерфейса. Их должен запускать
фоновый scheduler после подключения диска или изменения файлов.

Полный контракт: [File Search R1](../../Architecture/api/file-search-r1.md).
