# workspace-service

Core-хранилище единой рабочей области, а не набора чат-диалогов. Оно хранит
видимые сообщения 24 часа, текущие стадии работы и связь завершённого результата
с `task_id`. Task Ledger остаётся отдельной семидневной историей действий.

Workspace никогда не хранит chain-of-thought, traceback, model prompt или
диагностический payload. Фронтенд получает только текущую публичную стадию,
точное прошедшее время и безопасный результат.

Runtime публикует сообщения, последние runs и активные runs только через
аутентифицированный Unix socket. Благодаря этому панель после перезапуска может
восстановить текущую стадию и таймер, не сохраняя системные данные во frontend.

Перед Intent Compiler Workspace использует model-neutral capability router.
Сами включённые модули декларируют поддерживаемые цели и примеры в manifest.
Candidate router рекомендует ограниченный набор функций, но не решает, является
ли сообщение командой. Поэтому пустой candidate set больше не отправляет ввод
сразу в chat: Turn Router всё равно проверяет полный исходный текст. Для
системной или смешанной цели Qwen видит найденные операции, а при отсутствии
лексического совпадения — независимые module-owned признаки просьбы. Их
отсутствие больше не открывает весь список инструментов (ADR-021).
Ошибочно выделенный action-фрагмент, который потерял найденную capability,
отбрасывается в пользу semantic route исходного сообщения. Обычный разговор не
доходит до Intent Compiler или executor.

Malformed classification повторяется не более одного раза без истории, если
первый ответ мог быть загрязнён контекстом. Два невалидных ответа подряд всегда
завершаются chat/clarification без semantic tools, даже при сильном lexical
candidate.

Intent Compiler проверяет точный план. Результат операции формируется
детерминированным шаблоном из `OrchestrationResult`; отдельного model call ради
«найдено N файлов» нет. Подробная граница описана в `ADR-019`.

IPC-контракт для подключения frontend описан в
[`Architecture/api/workspace-runtime-v1.md`](../../Architecture/api/workspace-runtime-v1.md).

`attachments` — необязательный tuple `WorkspaceAttachment(kind, name)`, до 8
элементов, без чтения путей. В текстовом канале обработка недоступна:
`input_unavailable` сообщает об этом честно и блокирует операции для всего
сообщения. Файловую просьбу можно повторить отдельным текстовым сообщением без
вложения: пока нет обработчика, зависимость действия от картинки не угадывается.

Уточнение `copy_destination` сохраняется в SQLite на 10 минут для principal и
текущей коллекции. Короткий ответ о месте добавляется к исходной просьбе; новый
план проходит обычное подтверждение записи. Смена темы/отказ/TTL/другая коллекция
не запускают сохранённое действие.

Вместе с уточнением сохраняется неисполняемый черновик intent без destination.
Явный ответ Desktop/Documents/Downloads заполняет только эту роль. Повторная
классификация и повторный model route не выполняются: черновик снова проходит
Intent Compiler, capability boundary и Permission Gateway. Неоднозначный или
отрицательный ответ уничтожает одноразовое уточнение и не запускает действие.
