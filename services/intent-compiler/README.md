# Intent Compiler v1

По ADR-021 Ollama adapter не принимает выдуманную destination role: она должна
разрешаться из пользовательского текста. Имя папки Private не является ролью.
Неопределённое назначение возвращает ModelTurnKind.CLARIFICATION с ключом
copy_destination; workspace задаёт вопрос, сохраняя исходную просьбу. Ответ о
месте не заменяет последующее подтверждение R1. Системные итоги по-прежнему
приходят от исполнителя, не от свободного текста модели.

Intent Compiler преобразует естественный запрос в проверяемое семантическое
намерение и детерминированный план capability. Он **не выполняет** действия и не
содержит таблиц пользовательских фраз.

```text
текст пользователя
  → model provider: смысл и ссылки на фрагменты исходной фразы
  → strict validator: закрытая схема и безопасные аргументы
  → trusted task context: разрешение только символических ссылок
  → deterministic planner: capability, зависимости, риск, approval
```

Локальная модель, облачная модель и тестовый adapter реализуют один интерфейс
`IntentModelProvider`. Модель не видит реальные ID коллекций, пути назначения
или содержимое найденных документов. Доступные semantic functions формируются
не из списка внутри compiler, а из включённых capability-контрактов, для которых
в текущем executor есть handler и доверенная Permission Gateway policy.

Первый production adapter подключает локальный `qwen3.5:2b` через loopback API
Ollama. Qwen выбирает одну или несколько семантических функций; это не реальные
системные tools и они ничего не исполняют. Adapter преобразует выбор в AST,
добавляет безопасные зависимости и передаёт результат строгому валидатору.
Используются `think=false`, контекст 8192, bounded output, timeout 45 секунд и
`keep_alive=10m`. После прогрева локальный eval обычно выполняется заметно быстрее.

Workspace передаёт не более 12 последних разговорных сообщений и не более
8000 символов из уже существующего 24-часового хранилища. Системные стадии и
служебные notices в историю модели не входят.

Перед semantic route Workspace использует advisory candidate retrieval. Если
Turn Router уверенно распознал действие, отсутствие лексического кандидата не
превращает запрос в чат: provider получает операции, опубликованные включёнными
модулями. Вежливые вводные и благодарность не считаются отдельной разговорной
задачей. Негированные, гипотетические и capability-only вопросы не должны
создавать function call. Независимо от маршрута компилятор валидирует только
исходный пользовательский текст и закрытую схему.

Предмет запроса является ограничением поиска, а не декоративной частью фразы:
«PDF по математике» компилируется как `hybrid` с расширением и content term,
тогда как «все PDF» остаётся metadata-поиском. Исправление пользователя строит
новый поиск из текущего сообщения. Не реализованные Query Service фильтры не
публикуются модели и не могут быть молча отброшены.

`request_system_action` — безопасный fallback для системного намерения, которое
ещё не покрыто исполняемыми semantic tools. Оно никогда не становится планом:
backend сообщает об отсутствующем модуле и не вызывает executor.

Один runtime-каталог создаёт model tools, output schema, правила validator и шаги
planner. Capability, risk и approval больше не дублируются в Intent Compiler:
семантика приходит из Registry, исполнимость — из handler registry, а полномочия
— только из Permission Gateway. Копирование получает `R1` и подтверждение именно
из доверенной policy. Подробности зафиксированы в ADR-024.

Если для `copy_results` не указана системная роль назначения, adapter возвращает
`clarification` и неисполняемый intent без `destination`. Имя дочерней папки и
ссылка на результаты при этом сохраняются. Workspace может подставить только
явно выбранную роль Desktop/Documents/Downloads и повторно отправить intent в
обычные validation/planning/permission-границы без второго вызова модели.

Runtime endpoint: `POST /v1/intent/compile` с объектом `{"text": "..."}`.
Контекст продолжения диалога endpoint не принимает: его предоставляет runtime
из доверенного состояния текущей задачи. При обычном `--serve-panel` adapter
включён с моделью `qwen3.5:2b`. Флаг `--no-intent-compiler` отключает его.

Весами модели управляет first-party модуль `model.ollama`. Если Ollama доступен,
модуль автоматически запускает фоновый pull отсутствующей `qwen3.5:2b` и
передаёт Workspace безопасное состояние загрузки. Intent Compiler не содержит
кода установки или скачивания модели.

Запуск тестов из корня:

```bash
python -m pytest -q services/intent-compiler/tests
```

Реальные eval-тесты не входят в обычный CI и запускаются только явно:

```bash
AI_NATIVE_RUN_OLLAMA_EVALS=1 python -m pytest -q \
  services/intent-compiler/tests/test_ollama_live.py
```

Первый live-тест отдельно проверяет, что локальный API Ollama доступен и отдаёт
именно установленную `qwen3.5:2b`; остальные проверяют chat/action/mixed и планы.
