# ADR-039: Контракт файловых операций R1

**Статус:** принято 2026-09-22

## Контекст

Поиск документов и копирование найденной коллекции уже существуют, но MVP не
имеет единой модульной границы для создания папки, перемещения, переименования,
получения сведений и восстановимого удаления. Добавление этих команд напрямую в
ядро нарушило бы контрактную архитектуру и превратило бы маршрутизацию в набор
частных условий.

## Решение

Создаётся модуль `files.operations`. Первый
этап зафиксировал self-describing manifest, доверенные Permission Gateway policy
и проверяемые ограничения аргументов. Второй этап добавил изолированный
prepare/commit service. Третий этап подключил его через общий registry handler
и capability-neutral lifecycle, не добавляя файловые ветки в ядро.

R1 принимает существующие объекты только через серверную ссылку `results_from`.
Модель не получает абсолютные пути. Назначение ограничено ролями Desktop,
Documents, Downloads и ранее подтверждённым destination. Новое имя является
одним именем без компонентов пути. Конфликт по умолчанию завершает операцию
ошибкой; автоматическая перезапись отсутствует.

Уточнение от 2026-09-23: имя папки или новое имя объекта должно встречаться в
текущем запросе как самостоятельное имя. Если модель превращает `../escape` в
`escape` или придумывает другое имя, Intent Compiler отклоняет план до
исполнения. Planner также не выдаёт `READY`, когда за шагом с подтверждением
следует ещё один шаг: R1 остаётся единственной финальной границей, а
пользователь получает просьбу разделить действия на отдельные запросы.

Модуль предоставляет inspect, create-directory, move, rename и trash. Уже
существующая `storage.materialize.plan-copy` остаётся единственной copy-
операцией и используется через зависимость `storage.catalog`, чтобы две
семантически одинаковые команды не конкурировали в selector.

Manifest не назначает полномочия. Trusted core policy устанавливает R0 для
inspect и R1 с обязательным approval для каждой мутации. Write commit разрешён
только через internal или authenticated Unix transport. Безвозвратное удаление,
raw paths, overwrite, произвольная рекурсия, сетевые хранилища и архивы не входят
в R1.

## Последствия

- файловые операции расширяются модулем, а не условиями в ядре;
- capability публикуется только на пересечении enabled manifest, trusted policy
  и зарегистрированного handler;
- изолированный adapter повторно проверяет identity объекта перед commit,
  отклоняет symlink/reparse, path escape, replay, просроченный план и конфликт;
- move/rename выполняются только атомарно в пределах устройства, trash остаётся
  восстановимым, а пакетный сбой запускает rollback;
- runtime преобразует operation reference в доверенный collection id, а модуль
  не принимает model-owned пути;
- общий executor хранит opaque preparation, запрашивает подтверждение и только
  затем возвращает её тому же handler для commit;
- обновление default state применяется лишь пока пользователь явно не выбрал
  enabled/disabled, поэтому sync не перезаписывает пользовательское решение;
- лабораторные approve/deny, conflict, path-escape и mixed-language journeys
  собраны в отдельный focused-набор над production-модулем; подготовленный код
  не считается подтверждённым до отдельного запуска лаборатории.

Уточнение от 2026-09-24: inspect возвращает только метаданные из разрешённых
корней и отдельно считает элементы поисковой коллекции вне них. Один такой
элемент не скрывает сведения о разрешённых элементах; если разрешённых нет,
операция завершается стабильным кодом без раскрытия пути. Модуль поставляет
проверенные короткие RU/EN-сводки, а Workspace не просит модель выдумывать
итог файлового действия или размеры файлов.

Уточнение от 2026-09-25: optional `conflict_policy` объявляет в manifest
`implicitOmissionValue: fail`. Если модель ошибочно называет этот безопасный
умолчательный вариант «явно запрошенным», Intent Compiler **опускает** аргумент,
но не превращает модельное объяснение в пользовательское разрешение. Значение
`rename` по-прежнему требует проверки явного запроса. Метаданные допустимы
только для необязательного preserved enum; исполнитель сам применяет `fail`.
`directory_name` помечено ролью назначения, чтобы при составном запросе имя
целевой папки не становилось темой поиска содержимого.
