# ADR-002: Системный каталог хранилищ и виртуальные коллекции

**Статус:** принято 2026-08-18

## Контекст

Пользователь не должен знать или вручную указывать путь для каждого поиска. Он
формулирует цель естественным языком, например «найди все PDF по математике», а
система сама определяет доступную область поиска, типы файлов и подходящие
источники.

Нельзя реализовывать такой запрос полным обходом файловой системы при каждом
обращении: это медленно, создаёт лишнюю нагрузку и смешивает разные границы
доступа. Также нельзя автоматически копировать найденные файлы в новую папку:
копии занимают место, устаревают и изменяют состояние системы без отдельного
запроса пользователя.

В Linux единое дерево путей может включать системный раздел, отдельные диски,
сетевые ресурсы и временные виртуальные файловые системы. Тот факт, что ресурс
смонтирован в дерево, не означает автоматического разрешения на индексирование
его содержимого.

## Решение

### 1. Пользователь задаёт цель, система определяет пути

Публичный сценарий поиска начинается с запроса пользователя, а не с выбора
каталога. AI-слой интерпретирует цель и формирует структурированный запрос.
Детерминированные системные сервисы определяют область, выполняют поиск и
возвращают проверяемые результаты.

```text
«Найди PDF по математике»
  → structured search intent
  → разрешённые хранилища
  → фильтр PDF
  → поиск по содержимому и метаданным
  → ранжирование
  → виртуальная коллекция
```

Модель не обходит файловую систему и не открывает файлы напрямую.

### 2. Volume Registry

Система поддерживает реестр обнаруженных хранилищ. Для каждого хранилища
фиксируются:

- стабильный идентификатор и отображаемое имя;
- точка монтирования и тип файловой системы;
- доступность в текущий момент;
- граница файлового устройства;
- разрешение на каталогизацию метаданных;
- разрешение на индексирование содержимого;
- состояние и время последнего обновления индекса.

Системное пользовательское хранилище является исходной областью поиска.
Дополнительный, съёмный или сетевой диск обнаруживается автоматически, но поиск
его содержимого включается только после понятного разрешения пользователя.
Разрешение хранится для идентификатора хранилища, а не только для изменяемой
точки монтирования.

Сканирование одного хранилища не переходит через границу на другое
смонтированное файловое устройство. `/proc`, `/sys`, `/dev` и другие виртуальные
системные деревья обслуживаются специализированными инструментами, а не
индексатором пользовательских документов.

### 3. File Catalog и Content Index

File Catalog хранит актуальную карту доступных объектов:

- принадлежность хранилищу;
- путь и устойчивый файловый идентификатор, когда он доступен;
- имя, MIME/type, размер и время изменения;
- предполагаемую роль: документ, проект, конфигурация, лог, приложение и т. п.;
- класс чувствительности и состояние доступа;
- наличие извлечённого текста и состояние индекса.

Content Index хранит только извлечённые фрагменты и поисковые данные. Каталог
метаданных и индекс содержимого остаются разными слоями: система может знать о
существовании файла, не сохраняя его содержимое.

Изменения обновляются инкрементально. Периодическая сверка исправляет события,
пропущенные во время выключения, размонтирования или сбоя наблюдателя.

### 4. Результат поиска — виртуальная коллекция

Поиск возвращает виртуальную коллекцию ссылок на оригинальные файлы. Результат
содержит источник, хранилище, путь, релевантный фрагмент, статус доступности и
оценку релевантности. Файлы автоматически не копируются и не перемещаются.

Поддерживаются два представления:

- **умная коллекция** хранит запрос и обновляет состав при изменении индекса;
- **снимок** хранит конкретный набор ссылок, полученный в определённый момент.

Если хранилище отключено или файл перемещён, коллекция показывает это состояние,
а не выдаёт ссылку за доступный результат.

### 5. Материализация коллекции — отдельное действие

По явному запросу пользователь может создать каталог и материализовать туда
результаты:

- скопировать оригиналы;
- создать символические ссылки или ярлыки;
- сохранить manifest коллекции.

Перед выполнением система фиксирует снимок выбранных файлов и показывает число
объектов, общий объём, назначение, конфликты имён и недоступные источники.
Создание каталога и копий относится к изменяющей операции и проходит policy,
approval и audit. Перемещение оригиналов оценивается отдельно как более
рискованное действие.

## Последствия

- Пользователь ищет по смыслу, не оперируя путями.
- Поиск работает быстро за счёт каталога и инкрементального индекса.
- Дополнительные диски не становятся скрытым источником данных без разрешения.
- UI показывает результаты как коллекции, не создавая неявных дубликатов.
- Для реализации понадобятся Volume Registry, File Catalog, extractors,
  управление разрешениями и устойчивые ссылки на файлы.
- Текущий `services/indexer` становится реализацией Content Index и будет
  подключён к каталогу, а не заменён им.

## Не решается этим ADR

- окончательный дизайн экрана коллекций;
- полный список поддерживаемых форматов;
- выбор модели embeddings и reranker;
- правила автоматизации сайтов и приложений;
- формат синхронизации каталога между несколькими компьютерами.
