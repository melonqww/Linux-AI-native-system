# ADR-029: Lossless-аргументы модульных операций

**Статус:** принято 2026-09-11

## Контекст

После введения полного графа операций Qwen корректно восстановил пропущенную
операцию `copy_results`, но в английском сценарии потерял явно указанное имя
папки `Private`. Схема допускала копирование прямо в Desktop, потому что
`directory_name` является необязательным: копирование без дочерней папки тоже
является корректной командой. Поэтому обычная JSON Schema и проверка типов не
могут отличить законно отсутствующий аргумент от аргумента, потерянного моделью.

Делать `directory_name` обязательным нельзя, а добавлять в ядро языковые шаблоны
вида `folder called` или `папка с названием` противоречит модульной архитектуре и
не масштабируется на другие операции и языки.

## Решение

`user_intent` capability-контракта получает необязательный список
`preserved_arguments`. Модуль перечисляет в нём свойства своей закрытой входной
схемы, которые могут отсутствовать законно, но не должны быть молча потеряны,
если пользователь указал их явно. Registry проверяет, что каждое имя существует
в `input_schema`, и передаёт список в runtime-каталог `OperationDefinition`.

Ollama adapter после первоначального tool call выполняет узкий argument review
только для отсутствующих `preserved_arguments`. Review не видит дополнительные
capability и не исполняет операцию. Для каждого аргумента он обязан вернуть одно
из состояний:

- `present` с нормализованным значением и точной цитатой текущего сообщения;
- `absent`, если пользователь значение не задавал;
- `uncertain`, если значение нельзя восстановить надёжно.

Ядро независимо проверяет закрытую форму review, принадлежность аргумента
контракту, тип и ограничения значения, точное присутствие evidence в текущем
сообщении и буквальную связь свободного строкового значения с evidence.
Невалидный, неполный, противоречивый или неуверенный review не создаёт план:
система запрашивает уточнение. История диалога и proposed plan не считаются
источником полномочий.

Первым контрактом с этим свойством становится
`storage.materialize.plan-copy`: `directory_name` объявлен lossless-аргументом.
Знание о папках остаётся внутри storage-модуля; общий механизм не содержит слов
`Private`, `folder` или языковых регулярных выражений.

## Последствия и ограничения

- Явное имя дочерней папки сохраняется даже при дополнительном восстановлении
  составного графа и последующем уточнении Desktop/Documents/Downloads.
- Копирование непосредственно в выбранную системную папку остаётся допустимым:
  review возвращает `absent`, и искусственное имя не создаётся.
- Выдуманное значение без точного grounding не попадает в план.
- Дополнительный model-вызов выполняется только когда выбранная операция имеет
  отсутствующий `preserved_argument`; обычный чат и остальные операции его не
  оплачивают.
- Semantic review снижает, но математически не устраняет ошибки маленькой
  модели. Поэтому лаборатория всё равно должна отдельно проверять параметры
  плана до approve/deny. Такой oracle относится к следующему этапу тестового
  усиления и не заменяется этим runtime-контрактом.
- Отдельное различение тематического и точного фразового поиска этим ADR не
  вводится и остаётся следующим изменением.

ADR-029 дополняет ADR-022, ADR-024 и ADR-026 о самоописываемых контрактах,
runtime-каталоге и полных графах операций.
