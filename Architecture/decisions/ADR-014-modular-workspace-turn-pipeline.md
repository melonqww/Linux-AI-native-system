# ADR-014: Модульный Workspace Turn Pipeline v2

**Статус:** принято 2026-08-22

**Уточнение:** правило раннего перехода в chat при пустом candidate set заменено
решением [`ADR-019`](ADR-019-advisory-capability-routing.md). Остальные границы
этого решения остаются действующими.

## Контекст

Один запрос может одновременно содержать обычный вопрос и системное действие.
Tool call локальной модели не гарантирует текстовый ответ, а нулевой результат
поиска нельзя считать доказательством отсутствия файлов без полного индекса.

## Решение

Гибридный turn остаётся координацией модулей, а не новым монолитом:

- каждый включённый модуль может декларативно публиковать intent route:
  capability, semantic operation, описание и ограниченный набор примеров;
- model-neutral `CapabilityCandidateRouter` локально выбирает не более трёх
  кандидатов и не имеет доступа к исполнению;
- при отсутствии кандидатов весь запрос проходит как Qwen-chat без tools;
- при наличии кандидатов Qwen видит только соответствующие semantic functions,
  а вызов любой скрытой функции отклоняется provider adapter;
- проверенный model payload передаётся в `intent-compiler`, который предлагает
  действие и явный режим поиска;
- `query-service` исполняет только `metadata`, `content` или `hybrid` query;
- `index-scheduler` публикует полноту покрытия разрешённых дисков;
- `execution-orchestrator` возвращает типизированный `SearchOutput`;
- `workspace-service` сохраняет необязательную разговорную часть model route и
  добавляет проверенный task result системным шаблоном без финального Qwen-вызова;
- Permission Gateway остаётся единственным владельцем решения об исполнении.

Qwen не принимает решение об исполнении. Candidate router лишь ограничивает
набор доступных semantic functions данными включённых модулей. При отсутствии
кандидата tools физически не передаются модели. Наличие кандидата также не
является разрешением: model call, Intent Compiler и Permission Gateway независимо
проверяют operation, capability, аргументы, risk и approval. Попытка вызвать
скрытую функцию отклоняется provider adapter. Отключение модуля автоматически
убирает его маршруты и функции из Workspace.

Ошибка chat допускает один ограниченный повтор без истории и никогда не
переключается на tools. Количество, пути, полнота индекса и итог операции
создаются backend. Источник публичного сообщения равен `qwen`, `system`, `tool`
или `user`.

Разговорный ответ и преобразование ограниченного набора кандидатов в semantic
call работают локально через один заменяемый model provider. Текущая реализация
использует только `qwen3.5:2b` и не связывает ядро с Ollama. Контекст Qwen
ограничен 8192 токенами. Workspace передаёт ограниченную разговорную историю
без stages, notices и внутренних объектов исполнения.

## Последствия

Новые действия расширяют semantic tools и capability-модули, но не раздувают
Workspace и не дают модели прямого доступа к исполнителю. Старые планы поиска
без `mode` нормализуются детерминированно; новые model calls задают mode явно.
