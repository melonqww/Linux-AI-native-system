# ADR-014: Модульный Workspace Turn Pipeline v2

**Статус:** принято 2026-08-22

## Контекст

Один запрос может одновременно содержать обычный вопрос и системное действие.
Tool call локальной модели не гарантирует текстовый ответ, а нулевой результат
поиска нельзя считать доказательством отсутствия файлов без полного индекса.

## Решение

Гибридный turn остаётся координацией модулей, а не новым монолитом:

- model-neutral `turn-router` принимает от Qwen только закрытую классификацию
  `conversation`, `action`, `mixed` или `clarification`, а затем проверяет
  confidence и дословные непересекающиеся фрагменты исходного сообщения;
- чистая разговорная часть проходит отдельный Qwen-вызов без semantic tools,
  JSON-схемы и технической инструкции Intent Compiler;
- только проверенный action-фрагмент передаётся в `intent-compiler`, который
  предлагает действие и явный режим поиска;
- `query-service` исполняет только `metadata`, `content` или `hybrid` query;
- `index-scheduler` публикует полноту покрытия разрешённых дисков;
- `execution-orchestrator` возвращает типизированный `SearchOutput`;
- `workspace-service` связывает естественный ответ и проверенный task result;
- Permission Gateway остаётся единственным владельцем решения об исполнении.

Qwen не принимает решение об исполнении: неизвестный вид, низкий confidence,
выдуманный или пересекающийся фрагмент превращаются в clarification. Затем
Intent Compiler и Permission Gateway независимо проверяют capability, аргументы,
risk и approval. Количество, пути, полнота индекса и итог операции создаются
backend. Источник публичного сообщения равен `qwen`, `system`, `tool` или `user`.

Все три роли работают локально через один заменяемый model provider. Текущая
реализация использует только `qwen3.5:2b` и не связывает ядро с Ollama. Контекст
Qwen ограничен 8192 токенами. Workspace передаёт ограниченную разговорную
историю без stages, notices и внутренних объектов исполнения.

## Последствия

Новые действия расширяют semantic tools и capability-модули, но не раздувают
Workspace и не дают модели прямого доступа к исполнителю. Старые планы поиска
без `mode` нормализуются детерминированно; новые model calls задают mode явно.
