# ADR-025: Ограниченный локальный Semantic Capability Selector

**Статус:** принято 2026-09-09

## Контекст

После ADR-022 и ADR-024 модули публикуют единый самоописываемый контракт, а
runtime строит из него фактически исполнимый каталог операций. Лексический
`CapabilityCandidateRouter` хорошо закрывает быстрые RU/EN формулировки,
опечатки и часть сленга, но не может без словарей устойчиво связывать один смысл
на разных языках. Добавление синонимов в ядро для каждого нового модуля вернуло
бы архитектуру к растущей системе `if/else`.

Selector должен повысить recall, не превращая embedding-модель в новый источник
полномочий и не делая её обязательной для запуска Workspace. Он также должен
укладываться в зафиксированный ADR-022 локальный бюджет.

## Решение

В `turn-router` вводится provider-neutral `SemanticCapabilitySelector` и
loopback adapter `OllamaEmbeddingProvider`. Production использует локальную
модель `qwen3-embedding:0.6b`; она поддерживается тем же `model.ollama` lifecycle
под стабильным ID `semantic.selector`, является необязательной и загружается
только после решения пользователя.

Selector получает не manifests напрямую, а только `CapabilityDescriptor` из
снимка `OperationCatalog`. Поэтому в embedding-корпус попадает лишь пересечение:
включённый capability-контракт, зарегистрированный handler и доверенная policy.
Документ capability состоит из module-owned description и ограниченного числа
examples. Ядро не содержит синонимов конкретных файлов, PDF или приложений.

Операционные ограничения версии 1:

- максимум 128 descriptors и три возвращаемых кандидата;
- входной текст и embedding batch имеют жёсткие пределы;
- adapter принимает только credential-free HTTP origin на loopback;
- ответы Ollama ограничены по размеру, размерности и finite-значениям;
- embeddings каталога вычисляются лениво один раз на процесс, query cache —
  ограниченный LRU;
- timeout, malformed response или отсутствие модели дают пустой semantic-набор;
- после сбоя действует 60-секундный circuit breaker, чтобы не задерживать каждый
  пользовательский запрос.

`HybridCapabilityRouter` объединяет lexical и semantic scores и удаляет
дубликаты. Semantic-кандидат считается лишь независимым признаком того, что
сообщение следует передать Turn Router с ограниченным набором функций. Он не
объявляет сообщение действием. Qwen отдельно классифицирует `conversation`,
`action` или `mixed`, затем отдельно предлагает structured intent. Payload
повторно проходит schema validator, актуальный Operation Catalog, Permission
Gateway и Orchestrator.

ADR-026 дополнительно разделяет advisory `requested_operations` и консервативные
`required_operations`: semantic-кандидаты могут ограничить видимые функции, но
никогда автоматически не добавляются в обязательный исполняемый граф.

В стандартной детерминированной AI Scenario Lab используется lexical provider,
чтобы CI не обращался к сети и не зависел от весов. Live-lab с настоящим Ollama
подключает тот же hybrid selector, что production. Отдельный opt-in eval проверяет
реальную multilingual embedding-модель.

## Последствия

- Новый модуль становится доступен selector без правки центрального словаря.
- Межъязыковые и непривычные формулировки могут попасть к правильному малому
  набору tools, не расходуя контекст на весь каталог.
- Отсутствующая semantic-модель ухудшает recall, но не доступность системы.
- Ложный semantic-кандидат может увеличить число model calls, однако сам по себе
  не запускает executor и не расширяет разрешённые capability.
- Качество порога `0.55` и margin `0.08` должно калиброваться live-кампаниями;
  unit-тесты доказывают контракт и fail-safe поведение, но не качество весов.
- Одновременная установка всех необязательных моделей пока не обеспечена жёстким
  asset-budget enforcement; lifecycle обязан показывать каждую модель отдельно.

ADR-025 реализует отложенный semantic selector из ADR-022/024 и сохраняет границы
ADR-007, ADR-019 и ADR-021.
