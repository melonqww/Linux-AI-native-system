# ADR-036: пользовательские quick/full scan

**Статус:** принято и реализовано в `security.center` `0.7.0`.

## Решение

Показывать запуск проверки непосредственно во внутреннем экране Security Center.
Quick использует закрытый набор типичных точек заражения, full — все roots,
которые trusted runtime передал Module Manager. Отдельный файл и папка задаются
относительно home; UI не получает право передавать произвольный абсолютный путь.

Full может быть неполным из-за deadline, числа файлов, объёма или недоступных
объектов. Такой результат всегда `partial + unknown`. Модуль не получает root,
не следует symlink и не сканирует области, которых нет в bootstrap-конфигурации.

## Последствия

- quick соответствует пользовательскому ожиданию «проверить вероятные места»;
- full означает «всё доступное модулю», а не небезопасное чтение всей ОС;
- точечный folder scan повторно использует FileScanner для каждого кандидата;
- долгий scan пока синхронный; фоновые job/progress являются следующим этапом.

## Дополнение: desktop entry points

Ручной ввод пути в панели заменён на XDG Desktop Portal FileChooser. Это даёт
нативный выбор файла/папки без расширения полномочий runtime. Для Nautilus
используется официальный `MenuProvider`: он запускает отдельный bounded-клиент,
поэтому длительная проверка не выполняется в UI-процессе файлового менеджера.
Внешние drag-and-drop события GNOME Shell намеренно не используются: у них нет
стабильного контракта передачи локального файла в extension surface.
