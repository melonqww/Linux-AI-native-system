# ADR-021: Связь действия с просьбой, уточнения и факты о входных данных

## Основание

Принято 2026-09-03 после foundation-run `20260903T113742.684991Z` (56/87).
Английская арифметика порождала поиск, имя папки Private становилось destination,
маркер фото вызывал выдуманные описания/поиски, ответ объявлял невыполненную
фильтрацию. Часть image-провалов была ошибкой статусов самой лаборатории.

## Решение

Advisory retrieval остаётся, но уверенный classifier больше не разрешает
workspace выдавать модели весь каталог. Отдельный `requested_operations` в
turn-router ищет консервативные признаки просьбы по examples включённых модулей.
Examples начинаются с request cue; description служит только retrieval. Длинные
cue допускают одну опечатку, quoted examples и ближайшее отрицание исключаются.
Перед compiler proposed operations должны быть подмножеством requested operations.

Это не универсальное доказательство смысла: неузнанная формулировка может
потребовать перефразирования. Trade-off выбран вместо расширения прав после
ошибки Qwen. Правила остаются в router и module-owned примерах, не в ядре.
Legacy integration без capability router сохраняет прежний API; production
assembly и лаборатория используют настоящий router с новой границей.

Ollama adapter различает имя папки и destination role. Назначение не угадывается:
при отсутствии его в пользовательском тексте возвращается CLARIFICATION с
ключом copy_destination. Workspace хранит исходную просьбу и active collection
в SQLite на 10 минут для authenticated principal. Только явный короткий ответ
о месте продолжает её, заново проходя compiler и обычное R1 approval. Отказ,
смена темы, другая коллекция и TTL не исполняют старую операцию. Это не approval
и не автоматическое возобновление исполнения.

Workspace принимает bounded attachment metadata kind/name без путей и байтов.
В текстовом канале обработчика вложений пока нет: возвращается input_unavailable,
и инструменты не вызываются для всего сообщения: пока нет проверенного
результата обработки вложения, нельзя доказать независимость действия от него.
Даже отдельную файловую просьбу в таком сообщении нужно повторить текстом без
вложения. Текстовый [photo attachment] не является файлом.

Системные итоги строятся из результата исполнителя. Chat prompt запрещает
утверждения о новом выполнении и видении отсутствующего фото; presentation guard
блокирует распространённые RU/EN утверждения о выполнении без tool-result.
Это ограниченная защита, не полная семантическая проверка любых формулировок.

## Лаборатория и последствия

Адаптер различает clarification и unsupported. Английская journey отвечает на
вопрос о destination до отказа от approval. Фото-journey получает unavailable
metadata; запрещены любые capability calls, не только запись/vision. Два новых
regression-сценария воспроизводят найденные ошибки. Foundation-профиль: 91 позиция.

Frontend не меняется; новый kind может отображаться как системное сообщение о
недоступном вводе. Permission Gateway и исполнители не ослабляются. Старые
отчёты сохраняются неизменными; новый полный прогон выполняется после коммита.
