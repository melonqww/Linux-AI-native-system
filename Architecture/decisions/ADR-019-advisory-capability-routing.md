# ADR-019: Advisory capability routing для естественного пользовательского ввода

**Статус:** принято 2026-09-02

## Контекст

ADR-014 ввёл model-neutral `CapabilityCandidateRouter`, который ограничивал
доступные Qwen semantic functions декларациями включённых модулей. Первая версия
Workspace считала пустой набор кандидатов доказательством обычного разговора и
сразу вызывала chat. Такой порядок оказался слишком хрупким для нормального
пользовательского ввода: опечатка, сленг или длинная вежливая формулировка могли
не пройти лексический порог, поэтому model turn classifier и Intent Compiler
вообще не получали запрос.

Goal-driven AI Scenario Lab воспроизвела три независимых отказа: `дкоументы`,
`доки` и длинную просьбу с благодарностью. В последнем случае Qwen дополнительно
выделил благодарность как действие, хотя найденная capability относилась к
другому фрагменту. Все отказы происходили до executor и не создавали файловых
эффектов.

## Решение

Candidate router является только bounded retrieval-слоем высокой полноты:

- пустой набор кандидатов означает «лексический слой не уверен», а не «это чат»;
- при подключённом Turn Router каждое сообщение сначала получает проверенную
  классификацию `conversation`, `action`, `mixed` или `clarification`;
- обычный разговор никогда не достигает semantic tools, даже если содержит
  слова из описания capability;
- для `action` и `mixed` найденные кандидаты ограничивают набор функций Qwen;
- если классификатор видит действие, а кандидатов нет, Qwen получает только
  операции, опубликованные включёнными модулями, и выполняет semantic fallback;
- если action-фрагмент Qwen не сохраняет ни одной capability, найденной в полном
  сообщении, split считается ненадёжным: Workspace не отвечает на ошибочный
  conversation-фрагмент и маршрутизирует неизменённый исходный текст через уже
  ограниченный набор semantic functions;
- malformed/low-confidence classification без кандидатов остаётся безопасным
  разговором или уточнением и не открывает tool route;
- два malformed classifier-ответа подряд никогда не повышаются lexical
  candidate-ом до действия; ведущая RU/EN-негация обрабатывается общим safety
  guard как conversation, кроме конструкции «не только».

Лексический retrieval использует Unicode NFKC, token-level fuzzy comparison,
Damerau–Levenshtein для переставленных букв и лучшее ограниченное окно запроса,
чтобы длинная вводная часть не размывала полезную фразу. Описания и примеры
по-прежнему принадлежат module manifest. Ядро не содержит таблицу команд,
синонимов PDF или пользовательского сленга.

Нормализованный текст применяется только для retrieval. Turn Router, model
provider, Intent Compiler, evidence и audit получают исходную пользовательскую
строку. Ни candidate router, ни Qwen не разрешают выполнение: schema validation,
capability registry, Permission Gateway, risk class и approval остаются
обязательными независимыми границами.

## Последствия

Система устойчивее к опечаткам, многословию и неизвестному лексическому варианту,
не расширяя права модели. Тематически связанный разговор может попасть в набор
кандидатов, что допустимо: окончательное разделение chat/action выполняет Turn
Router, а наличие кандидата само по себе никогда не запускает executor.

Обычный разговор с production Turn Router требует classification и chat model
calls. Для действий без лексического совпадения добавляется bounded semantic
fallback. Это увеличивает latency по сравнению с ошибочным ранним chat-path, но
не увеличивает число загруженных моделей и обеспечивает корректность основного
сценария. Лаборатория обязана отдельно измерять false action rate, missed action
rate и случаи `intent_not_recognized`.

ADR-019 заменяет правило ADR-014 «при отсутствии кандидатов весь запрос проходит
как Qwen-chat без tools». Остальные границы ADR-014 остаются в силе.

Уточнение от 2026-09-03: ADR-021 отменяет расширение до всего каталога после
ошибки classifier. В production workspace инструменты ограничены независимо
найденными признаками просьбы; неоднозначность не расширяет доступ.
