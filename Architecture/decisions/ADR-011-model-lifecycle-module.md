# ADR-011: Жизненный цикл моделей как capability-модуль

## Статус

Принято и реализовано для Ollama v1.

## Контекст

Workspace и Intent Compiler должны использовать модель, но установка весов,
проверка локального inference provider и запуск его процесса не являются
обязанностями ядра. Эти механизмы будут меняться при добавлении других моделей
и providers. Встраивание `ollama pull` в Workspace связало бы ядро с одним
движком и дало бы сетевому lifecycle-коду лишний доступ к координации системы.

## Решение

Ядро сохраняет только model-neutral контракты маршрутизации и итогового ответа.
First-party модуль `model.ollama` предоставляет:

- `model.local.ensure` — неблокирующую подготовку настроенной модели;
- `model.local.status` — bounded состояние `starting`, `downloading`, `ready`,
  `unavailable` или `error` с безопасным прогрессом.

Модуль работает отдельным worker-процессом. Он обращается только к заданному
loopback Ollama origin, не использует proxy, `sudo` и shell-команды. Если Ollama
установлен, но сервер не работает, модуль может запустить фиксированную команду
`ollama serve` от текущего пользователя. Отсутствующие веса модели из
`AI_NATIVE_INTENT_MODEL` загружаются через streaming `/api/pull` в фоне.

Модуль не устанавливает системный пакет Ollama автоматически: это потребовало
бы привилегий и исполнения внешнего installer-кода. Такое действие может быть
добавлено только отдельным approval-gated deployment-механизмом.

Workspace запрашивает только публичный status. Пока модель загружается, запрос
не передаётся Qwen и пользователь получает безопасное сообщение с прогрессом.
Когда status становится `ready`, обычный model route выполняется без изменений.

## Последствия

- ядро не зависит от установки или API загрузки конкретной нейросети;
- новые providers смогут реализовать те же capability-контракты;
- загрузка весов не блокирует Unix IPC и запуск панели;
- отсутствие Ollama отличается от отсутствующей или загружаемой модели;
- network/process полномочия объявлены только у `model.ollama`.
