# ADR-024: Сквозной runtime-каталог пользовательских операций

**Статус:** принято 2026-09-05

## Контекст

ADR-022 сделал capability-контракт самоописываемым, но этого было недостаточно:
Intent Compiler сохранял собственные списки `OperationKind`, аргументов,
`operation → capability` и риска, а Ollama adapter — ещё одну таблицу tool-
описаний. Новый модуль формально регистрировался, но не мог пройти всю цепочку
без нескольких правок центрального кода. Расхождение таблиц также позволяло
показать модели операцию, которую текущий executor фактически не исполняет.

## Решение

Вводится неизменяемый `OperationDefinition` и собираемый на каждый актуальный
снимок `OperationCatalog`. Определение объединяет три источника:

- включённый `CapabilityContract` Registry поставляет operation ID, описание,
  примеры и закрытую входную JSON Schema;
- registry обработчиков Execution Orchestrator определяет, исполнима ли
  capability в текущем процессе;
- Permission Gateway назначает доверенные risk и approval policy.

Только пересечение включённого контракта, зарегистрированного handler и
доверенной policy попадает в каталог. Схема манифеста обязана быть подмножеством
разрешённых policy-аргументов, а обязательные policy-аргументы обязаны оставаться
обязательными в схеме. Несогласованный контракт отклоняется при сборке каталога.

Один и тот же снимок определений используется для:

1. JSON Schema запроса Intent Compiler;
2. semantic function tools локальной модели;
3. строгой проверки model payload;
4. преобразования операции в capability, risk и approval в planner;
5. дескрипторов advisory candidate router в production и AI Scenario Lab.

Статический enum операций и центральные таблицы удалены. Специальные проверки
URL, безопасного имени папки, search mode и server-owned `results_from` остаются
защитными инвариантами протокола v1, но не регистрируют операции и не выдают им
полномочия. `results_from` скрывается из model tool и добавляется adapter-ом как
ссылка на предыдущий шаг либо доверенный task context.

## Граница доверия

Манифест по-прежнему не может назначить risk, отменить approval, добавить scope,
transport или handler. Описание и схема помогают модели сформировать предложение;
Permission Gateway повторно проверяет фактический вызов. Candidate routing остаётся
подсказкой, а не разрешением.

## Последствия

- Новый исполнимый модуль с `user_intent` проходит model → validator → planner
  без изменения Intent Compiler и Ollama adapter.
- Отключённая capability или capability без handler не показывается модели.
- Добавление R2/R3 policy не требует расширять planner.
- Изменение набора модулей между model call и validation закрыто отклоняет
  устаревшую операцию.
- Семантический selector и автоматическая генерация handlers этим решением не
  реализуются; они остаются отдельными следующими шагами.

ADR-024 завершает runtime-проводку контракта из ADR-022 и сохраняет независимые
границы ADR-007, ADR-019 и ADR-021.
