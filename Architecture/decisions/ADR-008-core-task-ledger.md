# ADR-008: Core Task Ledger and user activity projection

## Статус

Принято для core v0.1.

## Контекст

Системе нужна долговечная история того, что она сделала: сколько объектов
обработано, какие файлы найдены или пропущены, ожидается ли подтверждение и чем
закончилась задача. Эта история должна переживать перезапуск runtime, но не должна
превращаться в debug console с traceback, исходным кодом, model reasoning и
техническими причинами ошибок.

Task Ledger относится к ядру. Модули и оркестратор публикуют в него ограниченные
структурированные факты, но manifest не может заменить его реализацию или схему.

## Решение

`services/task-ledger` хранит задачи, короткие lifecycle events, агрегированные
счётчики, ссылки на локальные объекты и версионированный safe checkpoint в SQLite.
Пользовательская проекция содержит только состояние и результат. Технический audit
остаётся отдельным каналом и не объединяется с Ledger.

Управляющая модель намеренно ограничена:

- работающая задача принимает cooperative cancel request;
- исполнитель останавливается на безопасной границе, выполняет cleanup и переводит
  её в терминальное `cancelled`;
- `cancelled` никогда не продолжается;
- только системное `interrupted` с сохранённым checkpoint допускает запрос
  продолжения;
- продолжение сначала запрашивается пользователем, затем атомарно принимается
  владельцем capability, который получает checkpoint;
- после перезапуска задача без safe checkpoint становится `failed`, а не
  угадывает место продолжения.

Обычная лента доступна read-only локальному runtime. Детали с путями и команды
cancel/continue разрешены только через authenticated Unix IPC. Loopback HTTP их
не предоставляет.

Терминальные задачи хранятся семь суток. Running, awaiting approval и interrupted
не удаляются retention cleanup. Ссылки показывают актуальную доступность файла,
но Ledger не копирует найденные файлы и не становится файловым каталогом.

## Последствия

Capability, которая заявляет resumability, обязана сохранять checkpoint только
после завершённой идемпотентной границы и самостоятельно реализовать продолжение.
Ledger не выполняет работу и не запускает плагины. Отмена также кооперативна:
принудительное убийство потока посреди записи запрещено, потому что может оставить
неопределённый результат.

Первая интеграция записывает жизненный цикл search/copy, найденные и созданные
файлы. OCR и индексатор смогут добавлять пропущенные повреждённые документы и
page/file checkpoints через тот же контракт без изменения ядра Ledger.
