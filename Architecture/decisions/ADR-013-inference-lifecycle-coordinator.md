# ADR-013: Единый inference lifecycle coordinator

## Статус

Принято и реализовано.

## Контекст

Ollama provider, Qwen и LLaMA имеют собственный жизненный цикл, но образуют одну
зависимую цепочку. Параллельные frontend-запросы создавали гонку: каталог моделей
мог прийти раньше provider status, а ошибки обоих запросов молча скрывались.

## Решение

Runtime публикует атомарный `inference.lifecycle.read`. Coordinator сначала
получает provider status, затем всегда получает каталог обеих моделей и строит
effective state. Исходные модули остаются независимыми capability providers, но
порядок и деградация принадлежат backend, а не UI.

Наличие бинарника (`installed`) больше не считается готовностью inference.
Модели разблокируются только при provider `state: ready`, подтверждённом ответом
loopback API. Это исключает ситуацию с двумя daemon-процессами и разными model
stores на одном компьютере.

Frontend использует один snapshot, показывает Ollama раньше заблокированных
моделей и продолжает bounded polling: быстро во время загрузки, редко в idle.
Ошибка транспорта или module worker теперь превращается в видимое публичное
окно, а не в пустой `catch`.

Runtime также обрабатывает systemd `SIGTERM` как контролируемое завершение,
закрывает Workspace и посылает shutdown всем module workers до выхода процесса.

## Последствия

- Qwen и LLaMA проверяются при каждом lifecycle refresh;
- невозможно предложить загрузку модели раньше готовности Ollama;
- частичный отказ provider/model модуля остаётся наблюдаемым;
- frontend больше не объединяет три независимых состояния;
- перезапуск user service не должен оставлять orphan worker-процессы.
