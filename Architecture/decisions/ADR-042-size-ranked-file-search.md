# ADR-042: Поиск файлов с ранжированием по размеру

**Статус:** принято 2026-09-26

## Контекст

Пользователь должен иметь возможность запросить самые большие файлы без ручного
задания расширения или каталога. Поиск не должен обходить весь диск при каждом
вопросе, читать содержимое файлов либо выдавать частичную выдачу за полный охват.
Новая возможность должна оставаться в существующем поисковом модуле и не вводить
специальный словарь пользовательских фраз в ядро.

## Решение

- `documents.query.search` публикует типизированные `sort_by` (`name_asc` или
  `size_desc`) и необязательный `limit` от 1 до 100. Capability-description и
  примеры объясняют модели семантику ранжирования. Для типичных явных запросов
  схема модуля дополнительно задаёт `explicitRequestCues`; общая проверка
  сопоставляет их только с текущим сообщением и не хранит словарь поисковых фраз.
- Для `size_desc` допустим только metadata-режим. Storage Catalog выбирает
  обычные файлы из доступных томов с разрешением и сортирует их по сохранённому
  размеру до применения лимита. Каталоги и symlink не выдаются; чтения файлов и
  нового обхода файловой системы нет.
- Если пользователь не указал количество, Execution Orchestrator задаёт лимит
  пять. Явный лимит передаётся без потери, а нечисловые значения и значения вне
  диапазона отклоняются.
- Search Coverage явно возвращает число доступных томов, исключённых из-за
  отсутствия разрешения. Результат дополнительно сообщает о неполном обходе и
  недоступных областях; список ограничен пятью безопасными фактами (имя, размер,
  имя родительской папки), без полного локального пути.
- Возможность не расширяет полномочия capability: запрос по-прежнему ограничен
  разрешениями файловых томов и проверками Permission Gateway.

## Последствия

- Запрос «найти самые большие файлы» может быть преобразован в обычный
  `metadata + size_desc`; отдельный обработчик фраз не нужен.
- Сортировка отражает состояние каталога на момент последнего успешного crawl.
  Новый или изменившийся файл может отсутствовать либо иметь устаревшие
  метаданные до следующего прохода scheduler.
- «На компьютере» означает доступные, разрешённые и каталогизированные тома, а
  не гарантированно каждый путь файловой системы. Не разрешённые пользователем
  тома не сканируются и явно обозначаются в coverage.
- Content/hybrid-поиск остаётся упорядоченным по релевантности; совмещение
  сортировки по размеру с поиском текста отклоняется.

## Проверка

Контракт capability, дефолтный и явный лимиты, запрет content-sort, исключение
томов без разрешения и безопасное пользовательское резюме покрываются
автоматическими тестами Query Service, Capability Registry, Orchestrator и
Workspace Service.
