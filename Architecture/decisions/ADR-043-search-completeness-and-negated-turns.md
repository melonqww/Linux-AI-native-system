# ADR-043: Полнота поиска по размеру и смешанные запросы с отрицанием

**Статус:** принято 2026-09-27

## Контекст

После полного прогона лаборатории обнаружились два расхождения между контрактами
модулей и общими проверками:

- Поиск самых больших файлов уже поддерживался Query Service и Orchestrator как
  `metadata + size_desc` без текстового, именного фильтра и расширения. Однако
  `ClarificationPolicy` требовала один из этих фильтров и останавливала запрос.
- `TurnRouter` считал любое сообщение с начальным отрицанием только разговором.
  Поэтому запрос «Не копируй файлы, а найди PDF» терял положительное действие,
  хотя маршрутизатор возможностей мог выделить поиск в следующей части фразы.

Оба случая затрагивают границу между модельным разбором и исполнением. Исправление
не должно разрешать неограниченный поиск или превращать отрицательную команду в
операцию записи.

## Решение

- Политика уточнения читает схему опубликованной операции и считает явно
  запрошенный параметр с выполненными `valueRequires` достаточным указанием цели
  поиска. Для текущего Query Service это `metadata + size_desc`; само значение
  `size_desc` в политике не зашито. Обычный поиск без содержательного условия
  по-прежнему требует уточнения. Ограничения схемы модуля сохраняются.
- Workspace Service передаёт в `TurnRouter` признак положительного действия,
  полученный из `required_operations` маршрутизатора возможностей. Он основан на
  описаниях и примерах модулей, а не на ответе модели или новом списке фраз.
- При начальном отрицании без такого признака сообщение остаётся разговором.
  При наличии признака модель может выделить отдельные точные фрагменты разговора
  и действия. Если она предлагает исполнить всё сообщение как одно действие,
  маршрутизатор возвращает уточнение без исполняемого фрагмента.
- После разделения Workspace Service передаёт компилятору только положительный
  фрагмент; состав операций дополнительно сверяется с распознанными и обязательными
  возможностями. Если отделение фрагмента превращает ранее запрещённую операцию
  в обязательную, запрос останавливается на уточнении. Отрицательная часть не
  даёт полномочий на запись.

## Последствия

- Запрос на самые большие файлы доходит до существующего поиска с лимитом по
  контракту ADR-042. Охват по-прежнему ограничен доступными и разрешёнными томами
  и состоянием каталога.
- Смешанный запрос с начальным запретом может выполнить позднее положительное
  действие, если оно подтверждено модулем и безопасно выделено в точный фрагмент.
  При неоднозначном разборе действие не выполняется.
- Новых правил для конкретных русских или английских фраз не добавлено. Качество
  выделения смешанного фрагмента остаётся зависимым от модели, но неоднозначный
  результат не повышается до действия.

## Проверка

Автоматические тесты покрывают поиск по размеру без фильтра, уточнение для
действительно пустого поиска, сохранение запрета для чистого отрицания, отказ от
неделимого действия с отрицанием, запрет повышения отрицательной операции при
неверном разделении и полный путь Workspace Service для запроса «Не копируй
файлы, а найди все PDF файлы». На 2026-09-27 целевой набор прошёл:
`221 passed, 10 skipped, 32 subtests passed` в расширенном наборе сервисов.

Полный лабораторный прогон 27 сентября был выполнен до этих изменений и не
подтверждает новую версию. Для публикации его результаты сохраняются как
исторические; новую версию необходимо отдельно проверить живым прогоном.
