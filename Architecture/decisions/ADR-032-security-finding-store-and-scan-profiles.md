# ADR-032: Finding Store и bounded scan profiles

**Статус:** принято и реализовано в `security.center` `0.4.0`

## Контекст

Версия 0.3 проверяла только один явно указанный файл. Для интерфейса уровня
антивируса нужны quick/full проверки и долговечная история обнаружений. При этом
неприемлемы произвольные абсолютные пути, бесконечный рекурсивный обход,
сохранение содержимого или ложный clean после частичного сканирования.

## Решение

Одиночный scanner остаётся единственным владельцем открытия и чтения файлов.
Новый coordinator лишь детерминированно перечисляет кандидатов внутри trusted
resource root и передаёт каждый через прежний `resource_id + relative_path`
контракт.

Профили имеют compile-time ceilings по файлам, байтам, глубине и времени.
`quick` оптимизирован для короткой проверки верхних уровней; `full` расширяет
границы, но всё равно не означает неограниченное сканирование всей ОС. Caller
выбирает только `resource_id` и имя профиля.

Подтверждённые observations сохраняются в отдельной SQLite-базе. Store выполняет
upsert по идентичности evidence, хранит только нормализованные метаданные и
возвращает bounded страницы. Чистые и unknown результаты не становятся
findings. Путь базы принадлежит trusted bootstrap, находится вне scan roots и не
принимается из capability payload.

## Инварианты

- перечисление не следует symlink и junction;
- каждый файл повторно проходит confinement и identity checks scanner;
- ошибка или предел кампании не преобразуются в clean;
- raw bytes и абсолютные пути отсутствуют в базе и ответах;
- повторное совпадение увеличивает occurrence count одной записи;
- запись findings не даёт права изменять проверяемый файл;
- manifest не может самостоятельно назначить risk или выдать scope.

## Последствия

Security Center теперь поддерживает привычные пользователю проверки одного
файла, quick и full для настроенных областей, а UI может показать журнал
подтверждённых угроз. Синхронный bounded coordinator подходит для MVP, но не
заменяет будущую очередь долгих фоновых задач.

Карантин, лечение, архивный анализ, обновление сигнатур, real-time monitor и
системный Ubuntu posture остаются отдельными этапами. Защита базы `0600` не
обещает устойчивость против root; более сильная tamper-evidence потребует
подписанного append-only audit trail и разделения процессов.
