# File Search R1

## Граница модулей

File Search не является частью ядра и не является одним монолитным плагином:

- `storage.catalog` обнаруживает тома, хранит разрешения и метаданные;
- `storage.watch` выполняет ограниченный фоновый crawl и продолжает checkpoint;
- `documents.index` хранит локальный SQLite FTS и состояния доступности текста;
- `documents.pdf` извлекает текст PDF и возвращает стабильный failure code;
- `documents.query` объединяет metadata/content/hybrid retrieval.

Отключённый модуль перестаёт публиковать capability. Интерактивный query не
сканирует диск и не открывает документы: эту работу заранее делает scheduler.

## Поиск

`POST /v1/search` остаётся совместимым и возвращает массив `results`.

`POST /v1/search-page` возвращает полный page envelope:

```json
{
  "mode": "metadata",
  "text": "",
  "extensions": ["pdf"],
  "volume_ids": [],
  "limit": 20,
  "offset": 0
}
```

Ответ содержит `results`, `offset`, `limit`, `total_matches`,
`total_is_exact` и `coverage`. Metadata total считается точно в каталоге.
Content/hybrid объединяет совпадения по уникальному пути и использует
ограниченный набор не более 10 001 кандидата. Если граница достигнута,
`total_is_exact=false`: число является честной нижней границей, а не ложным
утверждением о полном результате.

## Доступность содержимого

Каждый metadata-результат содержит размер, mtime и состояние:

- `indexed` — текст доступен локальному FTS;
- `pending` — файл поддерживается, но ещё не обработан;
- `unavailable` — файл найден, но текст не получен;
- `not_permitted` — для тома разрешены только метаданные;
- `unsupported` — тип не имеет text extractor.

`content_reason` использует ограниченные коды: например `too_large`, `damaged`,
`encrypted`, `needs_ocr`, `unreadable`. Внутренние exception и traceback в
контракт не попадают. Неудачная повторная обработка сначала удаляет старые FTS
chunks, поэтому изменившийся или сломавшийся документ не остаётся доступным по
устаревшему тексту.

## Покрытие

Coverage вычисляется только для запрошенных разрешённых томов. Оно отдельно
передаёт покрытые и сканируемые тома, число каталогизированных объектов и число
недоступных объектов. Нулевой результат считается полным только если все
выбранные тома завершили crawl. Повреждённый PDF не исчезает: metadata search
возвращает его с `content_state=unavailable`.

## Ограничения R1

- OCR подключается позже отдельным `documents.ocr`;
- отключённые и неразрешённые тома не сканируются;
- content/hybrid retrieval использует bounded candidate set;
- произвольное копирование и изменение файлов не входят в read-only search и
  проходят через отдельный Materialize Service с preview и подтверждением.
