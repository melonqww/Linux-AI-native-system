# Контракты Storage Catalog — v0.1

## Назначение

Storage Catalog объединяет три системных компонента:

```text
Volume Registry → File Catalog → Virtual Collections
                         │
                         └→ Content Index (отдельный сервис)
```

AI-слой формирует запрос по цели пользователя, но не задаёт разрешения и не
обходит файловую систему напрямую.

## Хранилище

```json
{
  "volume_id": "volume-d96f77c775184cfdf03a",
  "name": "System",
  "mount_point": "/",
  "device": "/dev/sda2",
  "fs_type": "ext4",
  "is_system": true,
  "is_removable": false,
  "is_network": false,
  "is_available": true,
  "permission": "content",
  "total_bytes": 512000000000,
  "free_bytes": 128000000000,
  "last_seen_at": "2026-08-18T00:00:00+00:00"
}
```

Уровни разрешения:

- `none` — хранилище известно, но его каталог недоступен для поиска;
- `metadata` — разрешена каталогизация имён, типов и других метаданных;
- `content` — разрешена передача допустимых файлов в Content Index.

`content` не отменяет правила чувствительных путей. Модель не может изменить
уровень разрешения полем поискового запроса. Изменение разрешения является
отдельным системным действием.

### Storage Enrollment API

Панель получает список автоматически обнаруженных дисков через защищённый Unix
runtime: `POST /v1/storage/volumes`. Поле `permission_required` показывает, что
дополнительный диск известен, но ещё не включён в индекс. Системный диск всегда
по умолчанию получает уровень `content`, но пользователь может отключить его;
дополнительный диск подключается отдельным вызовом
`POST /v1/storage/permission` с `none`, `metadata` или `content`. Loopback HTTP не
может читать точки монтирования и менять это разрешение.

После подключения `index-scheduler` подхватывает диск в фоне. Его frontier и
позиция в текущем каталоге сохраняются в SQLite без содержимого файлов. После
перезапуска обход продолжается с чекпоинта; максимум один ограниченный batch
может быть безопасно обработан повторно.

## Запрос File Catalog

```json
{
  "name_contains": ["algebra"],
  "extensions": ["pdf"],
  "roles": ["document"],
  "volume_ids": [],
  "limit": 100
}
```

Пустой `volume_ids` означает все доступные и разрешённые хранилища. Запрос не
содержит флага доступа к чувствительным данным. Обычный результат исключает их
независимо от текста модели.

### Результат каталога

```json
{
  "volume_id": "volume-d96f77c775184cfdf03a",
  "path": "/home/user/Documents/algebra.pdf",
  "stable_key": "2049:381924",
  "name": "algebra.pdf",
  "extension": ".pdf",
  "mime_type": "application/pdf",
  "entry_type": "file",
  "role": "document",
  "size_bytes": 2457600,
  "mtime_ns": 1787000000000000000,
  "sensitive": false
}
```

`stable_key` используется вместе с `volume_id`, чтобы попытаться восстановить
ссылку после переименования или перемещения. Путь остаётся обязательным fallback
и отображаемым источником.

## Виртуальная коллекция

### Smart collection

```json
{
  "collection_id": "uuid",
  "title": "PDF по математике",
  "kind": "smart",
  "query": {
    "name_contains": [],
    "extensions": ["pdf"],
    "roles": ["document"],
    "volume_ids": [],
    "limit": 100
  },
  "created_at": "2026-08-18T00:00:00+00:00",
  "updated_at": "2026-08-18T00:00:00+00:00"
}
```

Smart collection выполняет сохранённый запрос при каждом открытии и отражает
новые результаты.

### Snapshot

Snapshot не хранит запрос. Он содержит упорядоченные ссылки на конкретные
результаты. При разрешении ссылки каждый элемент получает `available`: `false`,
если файл исчез, диск отключён или разрешение отозвано.

```json
{
  "volume_id": "volume-d96f77c775184cfdf03a",
  "path": "/home/user/Documents/algebra.pdf",
  "stable_key": "2049:381924",
  "name": "algebra.pdf",
  "score": 3.14,
  "snippet": "...линейная алгебра...",
  "available": true
}
```

`score` и `snippet` заполняются объединённым query service после подключения
Content Index. File Catalog может вернуть их как `null`.

## Инварианты

- обнаружение хранилища не выдаёт разрешение дополнительному диску;
- модель и поисковый intent не могут выдать это разрешение;
- сканер одного тома не переходит на другое файловое устройство;
- отозванное разрешение немедленно скрывает ранее каталогизированные результаты;
- чувствительность не управляется данными от модели;
- коллекции не копируют и не перемещают оригиналы;
- materialize/copy будет отдельным policy-controlled инструментом;
- недоступный снимок сохраняет ссылку и явно сообщает состояние.
