# Структура проекта и пути — v0.1

## Референсная платформа

Для первой версии используется **Ubuntu Desktop 24.04 LTS с GNOME**. Разработка и CI сначала проверяют только эту комбинацию. Поддержка других дистрибутивов и desktop environments не входит в v0.1.

Ubuntu выбран как практичная база: LTS-версии стабильны, пакеты и документация широко доступны, а GNOME даёт нужные системные интерфейсы для уведомлений, порталов, accessibility и пользовательских сервисов.

## Пути на установленной Ubuntu-системе

Репозиторий не должен смешиваться с пользовательскими данными и рабочими файлами приложения. Предлагаемые пути для установки:

| Назначение | Путь | Правило доступа |
|---|---|---|
| Исполняемые файлы | `/usr/lib/ai-native-linux/` | Только установщик/администратор изменяет |
| Общая конфигурация | `/etc/ai-native-linux/` | R2/R3, резервная копия перед изменением |
| Пользовательская конфигурация | `~/.config/ai-native-linux/` | Владелец пользователя |
| Локальные данные и индекс | `~/.local/share/ai-native-linux/` | Владелец пользователя, opt-in источники |
| Кэш моделей | `~/.cache/ai-native-linux/models/` | Владелец пользователя, можно безопасно очистить |
| Логи и audit trail | `~/.local/state/ai-native-linux/audit/` | Владелец пользователя, секреты редактируются |
| systemd user units | `~/.config/systemd/user/` | Владелец пользователя |
| Временные sandbox-данные | `$XDG_RUNTIME_DIR/ai-native-linux/` | Удаляются после завершения сессии |

Никакие API-ключи, токены или пароли не хранятся в репозитории, `config/` или audit-логе. Для облачного провайдера используется системное хранилище секретов либо явно выбранный пользователем механизм.

## Первые реализуемые вертикальные сценарии

1. **System status:** панель показывает диск, CPU, RAM и батарею через инструмент только для чтения (R0).
2. **Systemd diagnosis:** агент получает статус выбранного пользовательского сервиса и релевантные логи, ничего не меняя (R0).
3. **Python workspace:** агент показывает план создания окружения; изменения выполняются только после явного подтверждения (R1/R2).

Каждый сценарий обязан пройти одну и ту же границу: `intent → policy → approval (если нужен) → tool → audit event → result`. Произвольный shell, `sudo` и работа от root не являются частью этих сценариев.
